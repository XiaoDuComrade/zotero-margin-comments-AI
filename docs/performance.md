# 页边批注压力测试

测试命令：`corepack pnpm run stress`

测试场景：单个 PDF 页面分别放置 50、150、300、600 和 1000 条左右混合评论；隐藏一半批注后恢复全部，再展开两侧边栏，连续触发 60 次滚动事件和 10 次缩放，每次缩放同步 4 帧。

| 当页评论 | 首次渲染 | 筛选一半 | 恢复全部 | 展开两侧 | 单次滚动 | 单个缩放帧 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 50 | 35.11 ms | 3.34 ms | 2.67 ms | 10.75 ms | 1.36 ms | 1.85 ms |
| 150 | 26.55 ms | 2.25 ms | 3.69 ms | 9.96 ms | 1.13 ms | 4.02 ms |
| 300 | 46.95 ms | 3.29 ms | 3.55 ms | 10.56 ms | 1.56 ms | 6.69 ms |
| 600 | 96.15 ms | 6.92 ms | 11.04 ms | 27.80 ms | 1.26 ms | 13.12 ms |
| 1000 | 133.48 ms | 9.43 ms | 13.74 ms | 46.20 ms | 1.77 ms | 19.70 ms |

表中的“单次滚动”是展开后页边栏自身的滚动和引线刷新。PDF 文档主滚动已回退到 0.6.3 的覆盖层和 `viewerContainer` 路径，不使用跨窗口固定画布或自定义滚动同步。筛选同步回调在压测中不超过 0.15 ms；插件等待 80 ms 让 Zotero 优先恢复原生侧栏，然后恢复当前页，其他页只在浏览器空闲时逐页处理。筛选和取消筛选只切换原有卡片的 class 并重排可见卡片，不销毁或重建 DOM。

这些数字来自 Happy DOM 算法与 DOM 操作压测，不包含 Zotero/Firefox 的真实排版、绘制和 GPU 合成成本。表中的筛选耗时是 80 ms 非阻塞等待之后的实际插件工作，不包含该等待时间。它适合发现复杂度问题和比较修改前后性能，不能替代真机帧率测量。按结果估计，300 条评论/页以内有充足余量；600 条/页以上属于极端密度，真机表现应另行观察。
